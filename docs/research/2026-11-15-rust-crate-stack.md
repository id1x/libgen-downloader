# Research: Rust crate stack for the rewrite

**Resolves:** id1x/libgen-downloader#17 ("Which Rust crates cover every subsystem without reinventing wheels?") · parent map #13
**Date:** 2026-11-15 · **Branch:** `research/rust-crate-stack` (throwaway, never merged — no PR)
**Method:** every version/status claim below was pulled from the crates.io API, GitHub Releases API, or the crate's own source/changelog on 2026-11-15. Subsystem needs were grounded in the TS source at `f5b0598` (cited inline).
**Doc location note:** the repo had no research-notes convention yet; this lives in `docs/research/` next to `docs/agents/`.

## Verdict on the sketched stack

The charting session's sketch (tokio / reqwest / scraper / ratatui + crossterm / clap / serde / ort / tokenizers) **survives validation**. Every choice is the maintained, dominant option in its slot as of Nov 2026, and no alternative is compelling enough to displace one. What the sketch missed — retry helpers, resume/range, asset embedding, cross-compilation tooling, per-platform ORT bundling — is filled in below, including one **target-level platform gap (macOS x64 vs ONNX Runtime prebuilts)** that needs an explicit decision in the spec.

## What the sketch missed — filled in

1. **Retry helpers** → reqwest::retry (client-level, since 0.12.23) + backon 1.6 for policy-level backoff (mirror cooldown's 15 s→300 s exponential + jitter). Avoid `backoff` (dead since 2021).
2. **HTTP resume/range** → reqwest supports Range natively, but current TS behavior is re-resolve-and-redownload, not byte resume. Flag for the spec: parity says keep re-download recovery; Range is a cheap, strictly-better add-on if the spec wants it (behavior change ⇒ explicit decision).
3. **Model-asset embedding** → `include_bytes!` + sha2 0.11 startup verification mirroring `scripts/models/manifest.ts` pinning (5.0 MB total assets).
4. **Cross-compilation tooling** → cargo-zigbuild (active) over cross-rs (dormant since 2023); linux-gnu over musl (ORT constraint); windows-x64 on an MSVC runner.
5. **ONNX runtime binary bundling per platform** → ort's `download-binaries` fetches per-target archives from pyke's CDN (`ort-sys/build/download/dist.tsv`, ORT ms@1.31.0) covering exactly: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `aarch64-apple-darwin`, `x86_64-pc-windows-msvc` (+EP variants). **No `x86_64-apple-darwin` entry.** Matches upstream: microsoft/onnxruntime dropped `osx-x86_64` and `universal2` prebuilt assets after v1.23.2 (v1.24.0+ ships `osx-arm64` only; confirmed across releases v1.21.0→v1.32.0). The TS app is unaffected (wasm backend). See Top risk #1 for options.
6. **SPA mirror needs no browser** — `libgen-spa-client.ts` is plain JSON REST (`/api/download/links-by-id`, `/api/decrypt`); reqwest covers it; no headless-chrome crate needed.
7. **Config/data directories** → `dirs` 7.0 (cache_dir matches the TS cache-dir logic exactly on all 3 OSes).

## Top risks (ranked)

1. **macOS x64 has no native ONNX Runtime prebuilt** — upstream ORT stopped shipping `osx-x86_64`/`universal2` after v1.23.2, and ort's own per-target CDN set (1.31.0) omits `x86_64-apple-darwin`. Options for the spec: (a) vendor the ORT 1.23.2 `onnxruntime-osx-x86_64` dylib and build that target with `load-dynamic` + a matching `api-N` feature (ort supports API levels 17–31; 1.23.x's C API is level ~23); (b) build ORT from source for macOS x64 in CI (macos-13 runner, cmake, ~20–30 min); (c) drop the macos-x64 target (behavior/parity decision — today's Bun build ships it). Decision needed in map #13's CI/build-matrix item; recommend (a) as the lowest-effort path that keeps the 5-target promise, validated by a CI smoke test of one real inference.
2. **ort is still 2.0.0-rc after ~2 years, MSRV 1.92, native C++ dep.** The rc line is widely used and actively released (rc.15, 2026-10-19), but "rc" means breakage between rcs is possible and the toolchain floor is new. Mitigation: pin exact rc, isolate inference behind a small trait so tract-onnx/candle (both pure Rust, both active) can substitute; re-evaluate when 2.0 stable lands.
3. **Tokenization parity is a verification task, not a freebie** — npm `@huggingface/tokenizers` is `tokenizers.js` (pure JS/TS reimplementation), not the Rust crate. The Rust crate is the reference implementation the JS one imitates, so drift is unlikely but must be proven: capture encode/pair-encode fixtures (query + candidate text, special tokens, truncation/padding config from `cross-encoder-settings.ts`) from the TS app and assert byte-identical ids in Rust tests (feeds #14/#18).
4. **Pre-1.0 churn + toolchain floor creep** — ratatui 0.30 restructured the crate family (pin exact versions; expect another breaking 0.31), reqwest 0.13 flipped TLS defaults, MSRVs are high (ratatui 1.88, ort 1.92). Pick the toolchain (stable ≥1.92), pin everything, and smoke-test cargo-zigbuild × aws-lc (reqwest's default rustls provider) in CI first — if aws-lc-sys fights the zig cross-toolchain, switch to ring via `rustls-no-provider` or native-tls.
5. **Linux musl is off the table for single-file distribution with native ORT** — gnu targets + ORT dylib handling (rpath or sidecar file) need a decision: statically link ORT where possible or ship the dylib inside/next to the binary. ort's prebuilts are dylibs; `copy-dylibs` + install-time placement or embedding+extraction to cache dir (mirrors the TS asset-fetch pattern) both work. Spec should name the mechanism.

## Alternatives considered and rejected

- **ureq** (blocking HTTP): would drop the tokio requirement for CLI-only operation, but the TUI + concurrent downloads + health monitors want async; reqwest is the safe standard. (isahc 2.0.2 is active again but curl-sys adds C build friction per target.)
- **smol/async-std**: async-std is deprecated (crates.io description); smol viable but ecosystem gravity is tokio.
- **cursive / tui-rs**: tui-rs archived (ratatui is its successor); cursive is app-framework-shaped, wrong fit for a 1:1 master/detail port.
- **argh / xflags**: fine but no advantage over clap for a 5-flag CLI.
- **hand-rolled retry/backoff**: the TS `attempt()` is small enough to mirror, but backon gives jitter/exponential for free and is active.
- **tract-onnx / candle as primary inference**: pure Rust (kills the bundling problem, including macOS x64) but unproven for this int8 cross-encoder's latency and numerics; keep as escape hatch, spike before switching.
